# golf-onefield

골프공 비행을 **장(field) 하나**로 계산하는 실험 엔진. Clarus Equation(CE)의 OBJ-04 구조
"세 힘 = 공통장의 투영, 중력 = 배경"을 골프공에 옮겼다.

공 표면 응력장 $\mathbf t(\mathbf x)$ 하나에서 항력·양력·스핀 감쇠 토크가 모두 투영으로 나온다.

$$
\mathbf F=\oint \mathbf t\,dA,\quad D=-\mathbf F\cdot\hat{\mathbf v},\quad L=\mathbf F\cdot\hat{\mathbf e}_L,\quad T_\omega=-\hat{\boldsymbol\omega}\cdot\oint \mathbf r\times\mathbf t\,dA
$$

## 모형

2차원(순수 백스핀)에서 장을 복소수 $\Gamma=C_D+iC_L$ 하나로 둔다. 무차원화
($L=2m/\rho A$, $U=\sqrt{gL}$, 시간 $U/g$)하면 공기밀도·질량·크기·중력이 모두 빠진다.

$$
\frac{du}{dt}=-|u|\,\overline{\Gamma(S)}\,u-i,\qquad \frac{dw}{dt}=-0.06\,w\,|u|,\qquad S=\frac{w}{|u|}
$$

힉스꼴 장 (각도 잠금):

$$
\Gamma(S)=(v_{\text{ev}}+h\,S)\,e^{i\pi/4},\qquad v_{\text{ev}}=0.388,\ h=0.271
\quad\Longrightarrow\quad |u|\,\overline{\Gamma}=(v_{\text{ev}}|u|+h\,w)\,e^{-i\pi/4}
$$

즉 $C_D=C_L$ 이고, 장 읽기에 나눗셈·초월함수가 없다.

### 3차원 장 (`field3d.py`)

스핀축 기울기 $a$ 를 더했다. $\hat\omega=(0,\sin a,\cos a)$, $k=(v_{\text{ev}}|u|+h\,w)/\sqrt2$ 일 때

$$
\frac{d\mathbf u}{dt}=-k\,\mathbf u+k\,(\hat{\boldsymbol\omega}\times\mathbf u)-\hat{\mathbf y}
$$

발사 방위각은 정확한 회전 대칭이고 $a\to-a$ 는 좌우 반전이라, 펼칠 축은 $(v_0',\theta,S_0,a\ge0)$ 4개뿐이다.
$a=0$ 에서 2차원과 1.6e-13 yd 일치, 두 대칭 모두 1e-12 yd 이하로 성립.
4차원 장 809,472점(6.5 MB), 4선형 읽기 최대 오차 0.19 yd.

러스트 판본(`flightbench/src/bin/field4.rs`, 파이썬과 7.7e-10 yd 일치):

| 방식 | 크기 | 최대 오차 (x / z) | 샷당 |
|---|---|---|---|
| 직접 적분 f64×8 | – | 0.0004 yd | 1,025 ns |
| 4차원 장, 4축 3차 | 7.3 MB | 0.012 / 0.002 yd | 333 ns (코어 확장 없음) |
| **각도 모드 전개 K=4** | **1.6 MB** | **0.014 / 0.005 yd** | **87 ns (2코어 1.9e7 샷/초)** |

기울기 축을 펼치는 대신 대칭을 꼴에 넣은 모드로 전개했다:
$x=c_0+c_2s^2+c_4s^4+c_6s^6$, $z=c_1s+c_3s^3+c_5s^5+c_7s^7$, $s=\sin a$.
계수 8개를 담은 3차원 장 하나로 4차원 장과 같은 정확도를 4.5배 작은 크기, 3.8배 빠른 속도로 낸다.
차원이 늘수록 펼치기의 이점은 줄어든다(3차원: 직접 적분 대비 16–34배, 사이드 스핀 포함: 약 12배).

### CE 최신 힉스 원리 반영 (`usga_v2.py`)

CE `ce-dimension-qgt-bridge` 브랜치의 2026-10-02 힉스 문서에서 두 원리를 가져왔다.

1. **$q[\langle\Psi\rangle]\neq\langle q[\Psi]\rangle$**: USGA 행은 샷 평균이므로, 보고된 입력 표준편차로 캐리의 분포 평균을 낸다.
2. **반경과 영향 결합** $R=\sqrt{2\Phi^\dagger\Phi}$, $g=\partial m/\partial R|_v$: 장을 배경(항력)과 스핀 들뜸(양력)으로 나누고 양력을 반경 노름으로 포화시킨 H2.

$$
C_D=v+d\,S,\qquad C_L=\frac{c\,S}{\sqrt{1+\lambda^2S^2}}
$$

$S\to0$ 에서 양력이 0 이 되고(각도 잠금의 반례 해소), 초월함수 없이 sqrt 하나로 계산된다. 매개변수는 PGA 로만 맞췄다.

| 캐리 RMSE (yd), USGA 20행 | B4 | F3 | Z0 | H2 |
|---|---|---|---|---|
| 평균 입력 하나 | 11.60 | 14.68 | 14.42 | 11.85 |
| **입력 분포 평균** | **8.96** | 12.09 | 11.92 | 9.93 |
| 분포 평균, 아마추어 16행 | 7.27 | 11.84 | 11.44 | **5.85** |
| 분포 평균, 평균 부호 오차 | +3.97 | +7.64 | +6.97 | **+1.65** |

원리 1은 모든 모형의 오차를 16–23% 줄였다. H2 는 아마추어·아이언에서 가장 좋고 치우침이 가장 작지만,
남자 프로 드라이버에서 분포 평균 -22 yd 로 무너진다(보고된 스핀 산포가 커서 저스핀 표본이 많다). 각도 잠금(F3, Z0)은 기본 장에서 내린다.

### 러스트 H2 엔진: 속도·수치 정확도 (`flightbench/src/bin/h2.rs`, `src/engine.rs`)

파이썬 엔진과 33행(PGA·LPGA·USGA 평균 입력) 최대 7.4e-10 yd 일치. 사이드 스핀 ±40° 무작위 3000샷, 기준은 f64 $dt'=0.0002$.

| 방식 | 샷당 (1코어) | 최대 오차 | 2코어 처리량 |
|---|---|---|---|
| 파이썬 solve_ivp | 약 15,000 µs | – | – |
| 이전 f64×8, 시간 걸음 (F3) | 1,025 ns | 4e-4 yd | – |
| f64×8, 시간 걸음, H2, 20걸음 | 804 ns | 6.1e-3 yd | – |
| **빠른 엔진 H2, 20걸음** | **176 ns** | **6.7e-4 yd** | **1.12e7 샷/초** |
| 빠른 엔진 H2, 40걸음 | 288 ns | 1.4e-4 yd (f32 바닥) | 6.6e6 샷/초 |
| H2 모드 장 K=4, 1.62 MB | 82 ns | 0.021 / 0.011 yd | 1.8e7 샷/초 |

빠른 엔진이 없앤 병목 (각각 측정으로 확인):

1. **sqrt·나눗셈 사슬**: $|u|=q\,\mathrm{rsqrt}(q)$, $|u|C_L=c\,w\,|u|\,\mathrm{rsqrt}(q+\lambda^2w^2)$. 나눗셈 0, rsqrt 2개(뉴턴 1회).
2. **자동 벡터화 실패**: 배열 클로저가 ymm 반쪽·memcpy·함수 호출로 쪼개졌다(14 ns/샷·걸음). 상태를 `__m512` 값으로 레지스터에 묶어 7.2.
3. **걸음 재매개** $d\tau=|u|^{1/2}dt$: 항력이 큰 고속 구간에 걸음을 몰아 같은 걸음 수에서 최대 오차가 1/10. 지수 0.3–1.5 를 훑어 0.5 를 골랐다.
   재매개 인자 $g=|u|^{-1/2}$ 는 근사 rsqrt14 그대로 쓴다: 모든 도함수에 같은 $g$ 가 곱해지므로 궤적은 같은 곡선이다.
4. **레인 대기**: 공이 떨어진 레인에 다음 샷을 바로 채운다. 착지 에르미트 보간은 16레인 벡터로, 결과는 마스크 scatter, 새 샷은 SoA 입력에서 마스크 expand-load.
   FSAL(다음 걸음의 $k_1$ 재사용)로 착지 양 끝 도함수가 공짜로 나온다.
5. 묶음 2개를 번갈아 돌리는 것은 순수 걸음에서 22% 이득이었으나 실제 엔진에서는 레지스터 압박으로 손해라 1개로 둔다.

모드 장은 셋째 축을 $\sigma=\sqrt S$ 로 폈다. H2 양력이 $S\sim1/\lambda$ 에서 꺾여 $S$ 등간격이 그곳을 놓쳤다(같은 크기에서 0.34 → 0.021 yd).
격자를 키워도 0.016 yd 에서 멈추는 것은 각도 모드 K=4 의 바닥이다. 직접 적분이 176 ns 로 내려와, 장 읽기의 이점은 2배 속도와 0.02 yd 정확도의 교환이 됐다.

통계 정확도: USGA 분포 평균을 행당 100만 표본(2000만 샷, 적분 2.8 s)으로 내면 표준오차가 0.045 yd 이하다.
파이썬 1500 표본(약 1.2 yd 잡음)을 걷어내도 순위는 그대로였다: 전체 B4 8.85 < H2 9.75 < F3 11.97 yd.

- **[반례] 캐리만으로는 장이 정해지지 않는다.** 항력과 양력이 바꿔치기돼 캐리는 1.7 yd 로 맞으면서 궤적이 13 yd 낮고 23° 납작하다.
  USGA 캐리도 이 꼴 오류를 못 잡는다(캐리만 맞춘 H2e 가 USGA 5.95 로 가장 좋지만 높이 −12 yd). 보정 기준을 세 양으로 바꾼다.
- 세 양 보정에서 **H2 와 B4 는 대등하다.** 자료 대비 물리 정확도의 압도는 없다. H2 의 이점은 같은 정확도를 `powf` 없이 내는 계산 쪽이다
  (f64 에서 B4 보다 약 4배 빠르고, f32 빠른 엔진에 그대로 들어간다).
- 남는 계통 오차: 아이언 착지각이 4–6° 얕고 PGA 드라이버 캐리가 −13 yd. 시험하고 기각한 보강:
  $C_D$ 의 $e/|u|$ 항, 스핀 감쇠 자유화(β→0 으로 가며 개선 없음), 레이놀즈 계단 $e/(1+(|u|/u_0)^2)$.
  $e/|u|$ 항과 계단은 훈련 착지각을 2° 로 줄이지만 보류 캐리가 LPGA 9–10 yd, USGA 12–13 yd 로 무너진다.

### 빠른 시험대: 항을 글로 바꾸고 1초 판정 (`flightbench/models.txt`, `src/bin/quick.rs`)

`models.txt` 에 항을 수식으로 적으면 다시 컴파일하지 않고 PGA 세 양 보정 → LPGA·USGA 판정까지 모형당 약 0.1 s 에 끝난다.

```text
[H2rat]
kd = v*u + d*w                 # |u| C_D   (변수 u, w, S, Re 와 매개변수)
kl = c*w*u/(u + l*w)           # |u| C_L
v = 0.24 0.05 0.6              # 시작 하한 상한 (값 하나면 고정)
```

```sh
cd flightbench
cargo run --profile quick --bin quick              # 모든 모형 + 기존 엔진, 약 1.5 s
cargo run --profile quick --bin quick -- H2rat     # 고른 모형만
cargo run --profile quick --bin quick -- --engines # 기존 엔진 대비 속도·수치 정확도
```

10분 걸리던 `calib` 와 같은 숫자가 나온다(H2 USGA 9.91 대 9.91). 줄인 곳: 궤적은 τ 걸음 RK4 약 56걸음(오차 1.7e-6 yd),
USGA 분포 평균은 몬테카를로 20만 대신 가우스-에르미트 343점(더 촘촘한 구적 대비 RMS 0.10 yd), 빌드는 `quick` 프로필(약 3 s).

### 기존 엔진 대비 (`src/openfairway.rs`)

비교 기준은 공개 골프 물리 라이브러리 [OpenFairway](https://github.com/digitalhand/openfairway)(Godot·C#, MIT)의 비행 물리를 러스트로 옮긴 것이다.
풍동 다항식 $C_D(Re)$, $C_L(Re,S)$ 에 보정 매개변수 55개와 발사 영역별 배율 31칸이 붙고, 120 Hz 반암시 오일러로 적분한다.
이식은 원본 회귀 시험 16개 중 14개의 창(비교값 ±2 yd) 안에 들고, 벗어난 둘도 1.08 yd 이내다(C# 을 직접 돌리지는 못했다).

| OpenFairway 1000 Hz | 497 µs | 0.12 yd |

### 실측 정확도 도전: 공유 포화 장 (`models.txt [공유]`, `models_tried.txt`)

판정 자료를 하나 더 붙였다. OpenFairway 저장소의 FlightScope Trajectory Optimizer 계산값 175샷(`fs_shots.csv`, 46–150 mph, 칩샷~드라이버, 스핀축 ±30°)이다.
실측이 아니라 상용 엔진의 계산값이고, OpenFairway 는 이 자료로 보정됐다. 우리 장은 이 자료를 훈련에 쓰지 않는다.

같은 프로토콜(PGA 12행 세 양, 가중치 1·1·1)로 꼴 11개를 시험해(`models_tried.txt`) 고른 장:

$$
C_D=v+d\,r,\qquad C_L=c\,r,\qquad r=\frac{S}{1+lS}\qquad\Longrightarrow\qquad |u|r=\frac{w\,|u|}{|u|+l\,w}
$$

스핀 항력과 양력이 **한 포화 $r$** 의 두 투영이다(항력 쪽에 배경 $v$ 가 더해진다). 매개변수 4개, 나눗셈 하나.

| RMSE | PGA 훈련 (캐리/높이/착지) | LPGA 보류 | USGA 캐리 (전체/프로/아마) | FS 캐리 (전체/<80 mph) · 높이 |
|---|---|---|---|---|
| **공유 포화 장** | **2.05** / **2.55** / **4.06** | 3.61 / **1.40** / **4.17** | 8.50 / **12.69** / 7.07 | **2.81** / 2.82 · **1.26** |
| H2 | 5.17 / 3.06 / 4.16 | 3.87 / 1.63 / 4.35 | 9.91 / 16.33 / 7.49 | 3.50 / 1.61 · 1.44 |
| OpenFairway + 같은 PGA 로 배율 2개 | 5.77 / 3.60 / 4.91 | **3.42** / 2.98 / 5.30 | **8.06** / 14.29 / **5.49** | 4.16 / 2.94 · 1.86 |
| OpenFairway 그대로 (FS 로 보정됨) | 9.82 / 4.18 / 7.44 | 6.09 / 3.31 / 5.04 | 9.31 / 14.21 / 7.61 | 2.30 / 2.00 · 1.67 |

- H2 대비 PGA 훈련 캐리 오차가 5.17 → 2.05 yd 로 줄었고, 모든 보류 지표가 같거나 좋아졌다.
- 같은 자료로 맞춘 기존 엔진(OF+2) 대비: 높이·착지각 전부, USGA 프로, FS 캐리·높이에서 이긴다.
  FS 를 훈련에 쓴 기존 엔진보다도 FS 높이가 정확하다(1.26 대 1.67 yd).
- **지는 곳**: LPGA 캐리(0.19 yd), USGA 아마추어 캐리(1.6 yd). 느린 공에서 항력이 오르는 항(Rcr)을 넣으면 USGA 아마추어가 3.5 yd 로
  좋아지지만 FS 느린 공이 5.7 yd 로 나빠진다. **실측 아마추어 평균과 FlightScope 계산이 느린 공에서 서로 다르다.**
  아마추어의 스핀축 기울기(슬라이스·훅) 산포가 수직 양력을 줄인다는 가설은 USGA 표에 축 자료가 없어 시험하지 못했다.
- 훈련을 PGA+LPGA 로 넓혀도(`--tour`) 같은 그림이다: USGA 8.40 대 8.16, FS 2.76 대 3.91.
- [주의] 판정 자료를 보며 꼴 11개 중 하나를 골랐다. 고른 모형의 보류 성적에는 고르기 효과가 들어 있다.
  또 착지각 가중치를 빼면(캐리·높이만) 캐리 지표가 모두 좋아지지만 착지각이 나빠져, 기준 프로토콜은 가중치 1·1·1 로 고정했다.
- 속도: 공유 장도 빠른 엔진에 그대로 들어간다. 샷당 202 ns, 적분 오차 최대 3.4e-4 yd (OpenFairway 120 Hz 58 µs·0.99 yd).

### 식 보강: 교차검증으로 고른 '공유 포화 장 + 항력 위기' (`models_search.txt`, `--cv`)

꼴 고르기를 판정 자료에서 떼어냈다. 투어 23행(PGA+LPGA) 안에서 한 행씩 빼고 맞춘 뒤 그 행을 맞히는 교차검증으로만 고르고,
USGA·FlightScope 는 고르기에 쓰지 않는다. 후보 13개 꼴을 약 19 s 에 훑었다.

$$
C_D=v+\frac{e}{1+(Re/Re_0)^4}+d\,r,\qquad C_L=c\,r,\qquad r=\frac{S}{1+lS}
$$

교차검증 1위(종합 2.82; 공유 3.22, B4 4.21, H2 4.30). 맞춘 $Re_0\approx6.3\times10^4$ 는 문헌의 골프공 임계 영역 $4$–$6\times10^4$ 근처다.

| RMSE | LPGA 보류 (캐리/높이/착지) | USGA (전체/프로/아마) | FS 캐리 · 높이 |
|---|---|---|---|
| **공유위기, PGA 만 훈련** | **2.85 / 1.73 / 3.18** | **7.34** / 15.11 / **3.21** | 4.28 · **0.51** |
| OpenFairway + 배율 2개, PGA 만 훈련 | 3.42 / 2.98 / 5.30 | 8.06 / **14.29** / 5.49 | **4.16** · 1.86 |
| **공유위기, PGA+LPGA 훈련** | (훈련) | **7.52** / 14.57 / **4.20** | **3.12** · **0.77** |
| OpenFairway + 배율 2개, PGA+LPGA 훈련 | (훈련) | 8.16 / **14.06** / 5.81 | 3.91 · 1.84 |

- 같은 자료로 맞춘 기존 엔진을 LPGA 세 양, USGA 전체·아마추어, FS 높이에서 이긴다. 진 곳은 USGA 프로 4행(0.5–0.8 yd)과
  PGA 만 훈련했을 때 FS 캐리(0.12 yd)다. 아마추어 캐리는 5.5 → 3.2 yd 로, 앞 단계에서 지던 곳이 가장 크게 이기는 곳이 됐다.
- 빠른 엔진: 샷당 193 ns, 적분 오차 최대 2.4e-4 yd. 역수 두 개를 rcp14 + 뉴턴 1회로 계산한다. 시험대 수식과 엔진 구현의 캐리 차 3.7e-6 yd.
- [주의] 이번 고르기는 훈련 자료만 봤지만, '느린 공에서 항력이 오른다'는 방향 자체는 앞 단계에서 USGA 아마추어를 보고 얻은 단서다.
  FS 는 실측이 아니라 상용 엔진 계산값이고, 항력 위기 항은 FS 빠른 공에서 오차를 늘린다(공유 2.71 → 4.37 yd).

### 힉스 × 클라루스 혼합 2차 고르기 (`models_search.txt` HC1–HC6, 2026-10-12)

힉스장(H2 의 반경 노름 $R=\sqrt{u^2+(lw)^2}$)과 클라루스장(공유 포화, 항력 위기)을 섞어 오차를 더 줄이는 꼴을 찾았다.
같은 교차검증 프로토콜(투어 23행 한 행 빼기, USGA·FS 는 판정에만)로 6개를 시험했다.

| 꼴 | 구성 | 매개변수 | CV 종합 | USGA 전체 / 프로 / 아마 | FS 캐리 · 높이 |
|---|---|---|---|---|---|
| **공유위기 (채택 중)** | 클라루스 포화 + 위기 | 6 | 2.823 | 7.52 / 14.57 / 4.20 | 3.12 · 0.77 |
| HC1 | 항력 클라루스, 양력 힉스 $R$ | 7 | **2.575** | 7.57 / 14.61 / 4.27 | 3.81 · 0.90 (제외) |
| **HC4** | 항력 포화만 $w/\sqrt{u^2+(lw)^2}$ | 6 | 2.606 | 7.42 / 14.78 / **3.77** | 3.72 · **0.69** |
| HC6 | 양력만 힉스 $R$ | 6 | 2.920 | 7.89 / 15.20 / 4.48 | 3.66 · 0.98 |
| HC5 | 포화·위기를 모두 $R$ 로 | 6 | 2.973 | 7.83 / 15.89 / 3.67 | 5.11 · 1.33 |
| HC2 | 위기 변수만 $R$ | 6 | 2.909 | 7.88 / 16.29 / 3.38 | 4.82 · 1.13 |
| HC3 | 항력 스핀 선형 (포화 없음) | 6 | 3.871 | 8.41 / 17.01 / 4.01 | 3.76 · 0.87 |

- **HC1 제외**: CV 가 가장 낮지만 적합이 퇴화했다. 항력 스핀 계수 $d$ 가 상한 5 에 붙고 배경 $v$ 는 0.03 까지 내려갔다. 상한에 붙은 적합은 정한 해가 아니다.
- **HC2·HC5**: 위기의 변수를 $|u|$ 에서 힉스 반경 $R$ 로 바꾸면 위기 세기 $e$ 가 상한 1 에 붙고 교차검증이 나빠진다(2.909, 2.973). 위기는 속도로 재는 것이 낫다.
- **HC4 가 CV 에서 0.22 yd 앞선다**(2.606 대 2.823, 매개변수 수 같음, 상한 안쪽). 그러나 보류 판정은 엇갈린다:
  아마추어 캐리 4.20 → 3.77 yd 로 좋아지고 FS 높이도 0.77 → 0.69 yd 로 좋아지지만, USGA 프로 14.57 → 14.78 yd 와 FS 캐리 3.12 → 3.72 yd 는 나빠진다.
- **결정: 채택 보류.** 이유는 두 가지다. 꼴 여섯 개를 더 놓고 고른 2차 선택이라 교차검증 1위에도 고르기 효과가 든다. 그리고 FS 캐리가 나빠져 순이득이 분명하지 않다.
  공개 TrackMan 실측 샷으로도 둘은 가려지지 않았다(아래 "실측 대조": 깨끗한 공 캐리 6.33 대 6.28 yd). 폰 영상 실측(M1)이 들어와도 같은 이유로 가려지기 어렵다면, 단순한 쪽(공유위기)을 유지한다.

### 실측 대조: 공개 TrackMan 드라이버 (`flightbench/src/bin/real.rs`, `tools/analyze_real.py`, 2026-10-12)

지금까지의 판정 자료는 투어 평균표, USGA 표, 상용 엔진 계산값이었다. 처음으로 **샷 하나하나의 실측**을 붙였다.
공개 TrackMan 드라이버 10,169샷([출처](https://github.com/tim-blackmore/launch-monitor-regression), 라이선스 표기가 없어 저장소에는 넣지 않고 `tools/fetch_trackman_public.sh` 로 받는다).
대부분 그물 앞 샷이라 캐리가 TrackMan 의 외삽이다(마지막 데이터 점 중앙값 6 yd). 그래서 **마지막 데이터 점이 캐리의 90% 이상이고 캐리 100 yd 초과인 920샷**만 채점했다(실외 연속 세션 3개).
입력은 기기가 잰 볼스피드·발사각·발사 방향·스핀·스핀축, 출력은 같은 샷의 Carry Flat 길이·옆 편차·최고 높이·착지각이다.
모형은 투어 23행으로만 맞췄고 이 자료로 다시 맞추거나 꼴을 고르는 데 쓰지 않았다. 기온·고도·바람 기록이 없어 대기는 보정하지 않았다(ρ = 1.2, 무풍).

**이 자료가 검증하는 것은 비행 모형이다.** 폰 영상에서 발사 조건을 읽는 부분은 검증하지 못한다(폰 영상 실측은 아직 없다).

공유위기 (RMSE / 평균 오차, 캐리·옆·높이는 yd, 착지각은 도):

| 부분집합 | 샷 | 캐리 | 옆 편차 | 최고 높이 | 착지각 |
|---|---|---|---|---|---|
| 추적 샷 전부 | 920 | 10.71 / +2.68 | 5.64 / −0.70 | 2.07 / +0.33 | 4.97 / +1.98 |
| **Premium·Limited Distance Soft 공, 25 yd 초과 4샷 제외** | 767 | **6.28 / +1.45** | 5.23 / −1.56 | 2.08 / +0.50 | 5.09 / +2.77 |
| Medium 공 | 149 | 12.15 / +10.24 | 7.43 / +3.64 | 1.86 / −0.55 | 3.82 / −1.87 |

### 공기역학 곡면 진단과 양력 위기 (`flightbench/src/bin/aeroflex.rs`, 2026-10-12 밤)

앞 절에서 식 한두 항(R1–R3, 위기 없음·지수 2, β 자유)으로 못 고친 **착지 속력·착지각** 결함을, 계수 곡면 자체를 자유 형으로 풀어서 다시 봤다.
실측은 같은 공개 TrackMan 드라이버 767샷(깨끗한 공, 25 yd 초과 제외, 연속 세션 4개)이고, 판정은 세션 하나씩 빼는 보류다. 이번에는 TrackMan 의 비행 시간(`Carry Flat - Time`)과 최고점까지 거리(`Max Height - Dist.`)도 채점에 넣었다.

**현재 기본 장 공유위기12 (PGA 12행만 훈련)**: 캐리 6.24 / +1.89, 옆 5.62 / −2.02, 높이 2.01, 착지각 4.91 / +1.86, 착지 속력 7.40 / **−4.98 mph**, **비행 시간 +0.11 s (같은 캐리에서 +0.20 s, 4%)**, 최고점 거리 +1.3 yd.

단서: **최고점 거리와 캐리는 맞는데 시간만 길다.** 내려오는 구간이 너무 느리고 가파르다(수평 속도가 더 많이 깎인다).

곡면을 풀어 보면 (세션 보류, 실측 + PGA 12행 훈련, LPGA·USGA·FS 는 맞춤에 안 씀):

| 꼴 (자유 매개변수) | 캐리 | 착지각 / 편향 | 착지 속력 / 편향 | 시간 편향 | LPGA | USGA 아마 | FS 캐리 |
|---|---|---|---|---|---|---|---|
| 공유위기12 (기준) | 6.25 | 4.91 / +1.86 | 7.40 / −4.98 | +0.11 | 2.78 / 1.68 / 3.06 | 4.64 | 3.33 |
| ΔC_D, ΔC_L 이중선형 표 (Re 5 × S 5, 51개) | 6.06 | 4.56 / +1.14 | 5.20 / −1.74 | +0.05 | 3.36 / 2.09 / 3.58 | 4.96 | 4.05 |
| C_D = f(Re) + d r (f 7마디) | 6.11 | 4.56 / +1.13 | 6.48 / −3.80 | +0.11 | 2.85 / 1.67 / 3.55 | 5.30 | 2.47 |

- **양력의 Re 의존이 열쇠다.** 배경 항력만 풀면(f(Re)) 착지 속력 편향이 −3.8 에 남지만, 양력 배율 g(Re) 를 같이 풀면 −0.4 mph, 시간 편향도 0 으로 닫힌다.
  풀린 g 는 Re ≈ 7×10⁴ 에서 0.47 까지 푹 꺼졌다가 9×10⁴ 에서 0.83 으로 돌아오는 좁은 골이다. 이 위치는 항력 위기(r0 ≈ 6.5–7.4×10⁴)와 같은 자리다.
  경계층이 층류에서 난류로 넘어가는 같은 Re 창에서 마그누스 양력도 변한다는 것은 물리적으로 말이 된다 (구 주위 흐름에서 알려진 임계 영역 현상). 하지만 **이 자료가 물리 계수를 증명하지는 않는다.**
- **매개변수 1개로 줄인 꼴 (공유위기12L)**: C_L = c r (1 − 4 a q (1 − q)), q = 1/(1 + (Re/r0)^12). 항력 위기 인자 q 에 그대로 묶인 봉우리라 중심·폭이 위기와 같고 새 매개변수는 깊이 a 하나다
  (중심·폭을 따로 풀면 a = 0.48, 중심 6.8×10⁴, 폭 11% 가 나와 거의 같은 꼴이다). 항력에 같은 봉우리를 더 얹어도 계수가 0 에 머문다.
  실측 포함 맞춤값: v 0.1354, e 0.1881, r0 68077, d 1.4080, c 2.6035, l 5.5338, a 0.413 (`Coef::SHARED_RE_L`). 식 해석기(`real`)와 러스트 클로저(`aeroflex`)로 따로 구현해 같은 값이 나왔다.
- **실측을 훈련에 쓰지 않아도 같은 방향이 나온다.** PGA 12행만으로 a 를 풀게 하면 a = 0.79 가 나오고, 아직 본 적 없는 실측 767샷에서 착지 속력 편향이 −4.98 → +0.57 mph, 캐리 편향 +1.89 → +0.20 yd 로 바뀐다

### 힉스·클라루스 3차: 계수 압축 사다리 (`flightbench/src/bin/compress.rs`, `models_search.txt` 3차, 2026-10-13)

CE 는 공동 응답의 맞춤 좌표를 26 → 4 → 0 개로 줄였다. 고정 분수를 쓰고, 운반자를 공유하고, 맞춤 대신 측정 입력 하나를 쓰고, 고르기 비용을 기록하는 방식이다.
같은 방법을 장에 옮겨 **"공유위기12 의 계수 6개 중 자료가 실제로 정하는 것은 몇 개인가"** 를 물었다. 고르기는 투어 23행 CV 와 아래 느슨한 방향 분석으로만 했다.
USGA·FS·공개 TrackMan 실측은 판정에만 썼다.

**느슨한 방향.** 투어 23행 최적점에서 $J=\partial r/\partial\ln p$ 를 구해 $J^\top J$ 를 고유분해했다. 고유값이 $2.5\times10^5$ 부터 $82$ 까지 3.5자리에 걸친다.
위 4개 조합은 ±0.4–6 % 로 정해지지만 아래 2개는 ±14 %·±25 % 다. 그 방향으로 10 % 옮겨도 잔차 RMS 가 0.009·0.003 만 오른다.
가장 느슨한 성분은 위기 세기 $e$ 다. 실측 767샷 블록만 봐도 같다.

**묶음 넷과 자기 일관성.** 묶음을 하나씩 넣고, 넣을 때마다 남은 하나를 다시 풀어 그 값이 묶음과 맞는지 봤다(투어 23행).

$$
C_D=v+\frac{1/4}{1+(Re/r_0)^{12}}+10v\,r,\qquad C_L=20v\,r,\qquad r=\frac{vS}{v+S}
$$

스핀 결합이 모두 배경 $v$ 에 비례하고, 들뜸이 배경 크기에서 포화한다. CE 힉스 문서의 "결합은 질량을 배경으로 나눈 것"($g=m/v$)과 같은 모양이다 [가설].

**결정.** 기본 장은 바꾸지 않았다(엔진·코어·웹 계수 그대로). K2 는 "같은 정확도를 맞춤 2개로" 내는 후보로 둔다.
프로젝트 규칙("실측으로 가려지지 않으면 단순한 쪽")으로 보면 K2 가 기본 장 후보다. 다만 묶음 값 1/4·1/2·1·20 은 투어 맞춤값을 본 뒤 골랐다(고르기 비용).
그래서 독립 자료 하나(폰 영상 M1, 다른 TrackMan·다른 공 세트)에서 공유위기12 와 같거나 나은지 확인한 뒤 바꾼다. K2 는 `SharedRe<12>` 에 계수만 넣으면 되므로 빠른 엔진·코어·웹 구현은 그대로 쓴다.

재현: `cd flightbench && MODELS=models_search.txt ./target/quick/quick "K5,K4,K3,K2,K1,K0,K2L" --cv --tour` (고르기),
같은 모형을 `--cv --tour` 없이 실행해 PGA 훈련 판정을 본다. 실측은 `TM_CSV=../data/real/external/trackman_public/data.csv MODELS=models_search.txt ./target/quick/real "K2,K2L" --pga --balls="Premium,Limited Distance Soft" --trim=25`.

#### 오차 예산: 어디를 더 낮출 수 있나 (실측 767샷, K2, 2026-10-13)

남은 실측 오차를 몫으로 나눴다. 세션은 행 번호 간격 40 초과로 나눈 연속 구간 4개(164·239·247·117샷)다.
'이웃 평균'은 발사 조건(볼스피드·발사각·스핀·축·방향)의 정규화 거리로 가까운 10샷의 잔차 평균을 뺀 값이다(자기 제외).
발사 조건의 매끄러운 함수로 설명되는 몫의 상한이다.

| 단계 | 캐리 | 옆 | 착지각 | 착지 속력 편향 |
|---|---|---|---|---|
| K2 그대로 | 6.25 (편향 +1.78) | 5.61 (−2.03) | 4.89 (+1.95) | −5.08 |

- **바닥은 4.7 yd 가 아니라 세션 안 약 2.9 yd 다.** 같은 발사 조건 쌍(볼스피드 ±2 mph, 발사각 ±0.8°, 스핀 ±200 rpm, 축 ±5°, 방향 ±2.5°)을 세션 안(74쌍)과 세션 사이(28쌍)로 나눴다.
  모형이 설명한 입력 차이를 뺀 잔차 차이는 세션 안 2.92, 세션 사이 4.50 yd 다. 캐리 차이를 그대로 쓰면 3.29·5.39 yd 다.
  앞 절의 4.7 yd 는 세션 사이(날씨·공 상태가 다른) 쌍이 섞인 값이다. 그래서 "남은 여지는 약 1.2 yd" 는 과소평가였다.
  제곱합으로 보면 K2 의 캐리 오차 중 바닥이 아닌 몫이 $\sqrt{6.25^2-2.92^2}\approx5.5$ yd 다.
- **기기 스핀축 배율 (새로 찾음).** 실측 옆 편차가 예측의 1.15 배다. 스핀축에 배율을 곱해 넣고(`real --axis-scale=`) 세 세션으로 고른 배율로 남은 세션을 채점했다.
  네 세션 모두 1.25–1.30 을 골랐고, 보류 옆 RMSE 는 5.61 → 4.45 yd 다. 캐리 편향은 +1.78 → −0.33 이 되고 캐리 RMSE 는 6.25 → 6.34 다.
  캐리까지 함께 보면 1.15–1.2 가 낫다(옆 4.5–4.7, 캐리 6.0). 원인 후보는 둘이다. TrackMan 의 축이 자기 비행 모형으로 추론한 값이라 우리 장과 정의가 어긋나거나, 우리 장의 옆 힘이 약하다.
  폰 측정은 우리 장으로 축을 역산하므로 이 배율이 저절로 흡수된다. **런치 모니터 자료를 입력으로 받을 때는 기기별 축 배율 1개가 필요하다** [가설: 다른 기기 자료로 확인 전].
- **양력 위기의 옆 편차 대가는 대부분 축 문제였다.** 축 1.2 에서 K2L 의 옆 편차는 4.92 로, 축 보정 없는 기본 장(5.62)보다 낫다. 남은 맞바꿈은 FS 와 투어 착지각이다.
- **세션(날씨) 몫은 작다.** 세션 편향을 빼도 캐리는 0.1–0.3 yd 만 준다. 옆 편차의 세션 편향(축 1 에서 −3.4 · −1.3 · −1.4 · −2.9 yd)은 옆바람 크기다.
  세션 안 시간 표류(세션 3: 100행에 −2.9 yd)도 있다. 기온·기압·바람 기록이 붙은 자료가 있어야 환경 입력(`golf-core` Env)을 판정할 수 있다.
- **가장 큰 남은 몫은 발사 조건의 함수다.** 이웃 평균이 캐리 6.25 → 4.96 yd 를 설명한다. 선형 회귀(7계수)는 5.56 까지만 설명하므로 비선형 구조다.
  볼스피드 155 mph 이상(54샷)은 RMSE 9.1 yd, 편향 +2.7 로 가장 나쁘다. 단 이 몫의 일부는 TrackMan 이 스핀·축을 자기 모형으로 추론한 데서 올 수 있다.
  이 자료에 구조를 더 맞추면 TrackMan 의 모형을 닮아 갈 위험이 있으므로 다른 기기(GCQuad·FlightScope 실측, 폰) 자료로 판정해야 한다.

재현: `TM_CSV=... MODELS=models_search.txt ./target/quick/real "K2,K2L" --pga --balls="Premium,Limited Distance Soft" --trim=25 --axis-scale=1.2 --dump=잔차.csv` 로 잔차를 뽑는다.
세션·이웃·쌍 분석은 잔차 CSV 에 같은 정의(세션 = 행 간격 40 초과, 쌍 조건 위)를 적용한 것이다.

### 러스트 코어 → wasm: 정밀도와 속도 (`golf-core/`, 2026-10-12)

채택 장(처음엔 공유위기 n = 4, **같은 날 밤에 공유위기12 로 교체** — `engine::default_field()` 와 같은 계수, PGA 12행 잔차를 `flightbench` 와 행별로 대조해 일치)을 `flightbench` 와 떨어진 이식용 크레이트로 옮겼다.
아래 표의 수치는 교체 전(n = 4) 측정이다. 교체 뒤 다시 잰 값(같은 4000샷, 한 코어): 네이티브 f64 τ 0.137 1.82 µs·τ 0.05 4.6 µs(오차 9.5e-6 yd), f32 4레인 0.66 µs, wasm SIMD 0.68–0.75 µs, 순수 JS f64 3.3–4.5 µs.
τ 0.137 의 최대 오차는 가파른 위기 때문에 4.4e-4 → 5.6e-4 yd 로 조금 커졌다 (RK4 절삭, f64 도 같다). 양력 위기 항(+4a q(1−q))의 비용은 샷당 수 %다.
3차원 비행(사이드 스핀 포함), f32/f64 제네릭, 걸음 재매개 RK4, 착지·최고점은 에르미트 보간. 웹용은 `wasm-bindgen` 으로 내보낸다.

- 검산: PGA 12행 잔차를 `flightbench` 의 같은 장(`quick --rows`)과 대조하니 36개 값이 모두 0.1 yd 안에서 같다 (`cargo run --release --bin bench -- rows`).
- 시험: 단위 시험 5개(7번 캐리 범위, 걸음 수렴, f32 대 f64 1 yd 이내, 좌우 대칭, 경로 끝점이 착지점).
- wasm f64 대 네이티브 f64: 최대 상대 차 9e-16 (같은 연산, 같은 답).

샷 4000개 (볼스피드 60–180 mph, 발사각 5–35°, 스핀 1500–10000 rpm, 축 ±30°, 저불일치 수열). 기준 = f64 τ 0.002 (걸음 1374).

  기준(τ 0.002)의 자기 오차는 같은 수렴률로 추정하면 1e-10 yd 근처다(직접 재지는 않았다).

#### 속도·환경 강화 (같은 날 뒤, 상세는 `golf-core/RESULTS.md`)

위 표의 스칼라 판본을 고치고, 4레인 SIMD 커널과 환경 입력(바람·공기 밀도·점성)을 더했다. 아래 시간은 조용한 기계에서 내가 다시 잰 값이다(에이전트의 최소값 589 ns 보다 느리게 나왔다. 측정 잡음 ±20–30%).
샷 4000개, 기준 f64 τ 0.002.

| 방식 (τ 0.137, 샷당) | 전 | 후 | 캐리 최대 오차 |
|---|---|---|---|
| 네이티브 f64 스칼라 | 3.22 µs | **1.59 µs** | 4.4e-4 yd |
| 네이티브 f32 4레인 (SSE 자동 벡터화) | – | 0.63 µs | 4.4e-4 yd |

- **기존 엔진 대비**(같은 기계, 우리 쪽은 wasm 이라 더 불리한 쪽): wasm SIMD 는 OpenFairway 원본 설정보다 **약 57배 빠르고 적분 오차가 2,300배 작다**. 정밀하게 풀어도(네이티브 f64 τ 0.05: 4.2 µs, 7e-6 yd) OpenFairway 1000 Hz(357 µs, 0.117 yd)보다 약 85배 빠르고 1.6만 배 정밀하다.
  네이티브 AVX-512 판본은 0.155 µs 로 약 260배다.
- **스칼라 2배의 정체**: 걸음당 비용은 15%만 줄었고, 대부분은 56회 이분법(분기 예측 실패)을 뉴턴 4–5회로 바꾼 것이다. 긴 비행(τ 0.05)은 1.4배만 빨라졌다(걸음 지배).
- **SIMD 커널**: 4개 샷을 한꺼번에 적분하고 착지·정점 사건이 나면 그 레인만 스칼라 f64 로 처리한 뒤 다음 샷을 채운다. 스칼라 f32 와 **샷마다 비트까지 같다**(차이 0). SIMD 가 없는 wasm 에서는 스칼라 f32 로 위임하고 기본 빌드(`pkg/`)는 SIMD 를 쓰지 않는다.
  Ray-Ban Display 브라우저가 wasm SIMD 를 지원하는지는 모른다(점검 페이지로 확인). `js/load.mjs` 가 검사해서 `pkg-simd/` 또는 `pkg/` 를 고른다.
- **τ 0.137 의 오차 4.4e-4 yd 는 f32 바닥이 아니라 RK4 절삭 오차**(f64 도 같다). 낮고 느린 샷(3–5걸음)이 최대 오차를 만든다. 선택 `min_steps = 6` 이면 걸음 +3.5% 로 2.1e-4 yd. 기본은 꺼져 있다.
  카한 보상 합(f32)은 τ 0.05 오차를 1.9e-4 → 2.8e-5 yd 로 줄이고 비용이 없다.
- **환경 입력**(`Env`, `fly_env`, `batch_*_env`): 기온·고도(ISA 기압, 이상기체, 서덜랜드 점성), 바람(상대속도). 갈릴레이 불변(수평 바람 = 바람 없는 공기에서 속도 `u0 − w` 로 쏜 비행 + `w·T`)이 상대 1e-9 로 맞고,
  m·s·kg 단위 직접 적분과 캐리·편차 2.5e-8 m 로 일치한다. 드라이버 167 mph: 해수면 15 °C 269.1 yd → 1600 m 20 °C 282.0 yd (+4.8%). 맞바람 5 m/s −7.7%, 뒷바람 5 m/s +5.9%.
  **환경 효과는 실측으로 검증하지 못했다**(공개 자료에 기온·고도·바람 기록이 없다). 물리 일관성(불변·단위 직접 적분·단조성)만 확인했다.
  느린 공은 따뜻해지면 오히려 0.3 yd 줄어든다: 점성이 올라 Re 가 내려가 항력 위기 속도가 올라가기 때문이다(Re 연동의 결과, 검증 안 됨).
- **확인 못한 것**: 폰·안경 CPU 속도(ARM NEON 에서 f32x4 sqrt/div 가 느릴 수 있다. PRD 의 "폰 ≤ 1 µs" 는 데스크톱 0.6–0.7 µs 로 여유가 크지 않다), 브라우저 SIMD(Node 만 돌렸다), f64 SIMD(미구현).
- 총거리용 롤 모형(`golf-core/src/ground.rs`, 위 "착지 상태 결함과 총거리")과 착지 속력 `land_mph` 도 코어에 들어갔다(드라이버 발사 범위에서만 `total_reliable`).

### 스핀 역보정 (`flightbench/src/bin/spininv.rs`, `web/spin_inverse.html`)

폰 카메라로는 스핀을 직접 재기 어렵다(240 fps 에서 3000–9000 rpm 이면 프레임 사이 75–225° 돌아 바퀴 수를 못 셈).
그래서 비행 초반 프레임의 공 위치에 장을 맞춰 스핀을 거꾸로 찾는다. 미지수 8개(첫 위치 3, 볼스피드·발사각·방위각, 스핀, 축),
사전분포는 투어 회귀 $\text{rpm}\approx2233+304\,\theta-9.9\,v_{\text{mph}}$ ± 1500 rpm 과 축 0 ± 20°.

러스트 몬테카를로 60회 (공 뒤 카메라, 240 fps, 위치 노이즈 σ 5 mm, 깊이 축 ×5):

| 관측 | 0.05 s | 0.1 s | 0.2 s | 0.3 s | 스핀 모름 |
|---|---|---|---|---|---|
| 드라이버 캐리 오차 yd | 9.72 | 5.34 | **0.75** | **0.32** | 7.1 |
| 드라이버 스핀 오차 rpm | 1247 | 746 | **136** | **49** | – |
| 7번 캐리 오차 yd | 3.36 | 2.35 | **0.99** | **0.43** | 3.0 |
| 드라이버 비행 거리 | 3.7 m | 7.3 m | 14.5 m | 21.4 m | |

- 비행 10–15 m(0.2 s)를 5 mm 정밀도로 보면 드라이버 캐리 오차 0.75 yd, 스핀 ±136 rpm, 축 ±1.7° 다.
- 실내 매트·네트(3 m, 0.05 s 이하)로는 스핀이 안 보인다. 그때는 사전분포로 돌아가 드라이버 ±7–10 yd, 아이언 ±2–3 yd.
  이 장에서는 아이언 캐리가 스핀에 둔해서(포화 $r=S/(1+lS)$) 짧은 관측으로도 아이언은 쓸 만하다.
- 웹 페이지: WGSL 격자 탐색(스핀 96 × 축 48 × 발사각 12 × 방위각 12 = 66만 후보) → JS LM → 사후 표본 40개로 캐리 불확실도.
  JS 엔진은 러스트와 프레임 위치·캐리가 소수 9자리까지 같고, GPU(f32) 격자와 CPU(f64) 격자의 제곱오차 차는 1.6% 이내, 최솟값 위치는 같다.
  실제 측정 프레임(t x y z)을 붙여 넣어 역보정할 수 있다. 공 검출(영상 → 프레임 위치)은 아직 없다.

#### 장 역산: 궤적 적분 없이 장의 닫힌 꼴로 거꾸로 풀기 (`flightbench/src/bin/fieldinv.rs`, 2026-10-13)

지금까지 역보정(`spininv`, `screen`)은 장을 미분방정식의 힘으로만 썼다. 8 매개변수 LM 이 수치 야코비안을 구할 때마다 궤적을 다시 적분해서, 샷당 적분이 300–500번이다.
장은 닫힌 꼴이라 직접 거꾸로 풀 수 있다. 관측 창 가운데에서 가속도를 재면 다음처럼 풀린다.

$$
\mathbf A=\mathbf a_c+g\hat{\mathbf y},\qquad C_D=-\frac{\mathbf A\cdot\hat{\mathbf v}\,L}{|\mathbf v|^2},\qquad C_L=\frac{|\mathbf A_\perp|\,L}{|\mathbf v|^2},\qquad
r=\frac{C_L}{c}\ \ \text{또는}\ \ r=\frac{C_D-v-e\,q(Re)}{d},\qquad S=\frac{r}{1-l\,r}
$$

항력과 양력이 같은 포화 $r$ 의 두 투영이라는 장의 구조(공유 포화) 덕분에 스핀 비가 두 번 관측된다. 노이즈 가중으로 합치고 사전분포와 가우스로 합친다.
스핀축은 양력 방향 $\hat{\mathbf n}$ 에서 나온다: $a=\operatorname{atan2}(-\hat{\mathbf n}_h\cdot\hat{\mathbf n},\ \hat n_y)$.

- **B 장 역산 (대수)**: 축마다 2차 맞춤 → 위 식. 적분 0번, 샷당 2–3 µs.
- **C 닫힌 꼴 궤적 GN**: 궤적을 가운데 시각의 테일러 3차($\mathbf A$ 와 저크를 장의 닫힌 꼴로)로 쓰고 8 미지수를 가우스-뉴턴 3번 맞춘다. 적분 0번, 장 계산 약 80번, 샷당 15–60 µs.
- 끝에 착지는 앞으로 한 번 날린다(빠른 엔진 0.2–1 µs).

옆 카메라 240 fps, 위치 노이즈 σ 5 mm (깊이 ×5), 몬테카를로 60회. RMS 스핀 rpm / 캐리 yd 와 역산 시간이다.

|---|---|---|---|
| 드라이버 0.1 s | 967 / 9.32 · 2.6 µs | 594 / 5.68 · 22 µs | 592 / 5.66 · 5.0 ms |
| 드라이버 0.2 s | 133 / 2.32 · 2.8 µs | 127 / 2.29 · 36 µs | 126 / 2.30 · 8.6 ms |
| 드라이버 0.3 s | 48 / 0.93 · 3.2 µs | 48 / 0.85 · 53 µs | 48 / 0.85 · 11.0 ms |
| 7번 0.2 s | 686 / 1.91 · 2.9 µs | 558 / 1.38 · 36 µs | 558 / 1.39 · 9.3 ms |
| 웨지 0.3 s | 716 / 0.39 · 3.3 µs | 747 / 0.42 · 52 µs | 725 / 0.41 · 11.6 ms |
| 뒤 카메라 드라이버 0.2 s | 183 / 1.07 · 2.9 µs | 149 / 1.00 · 38 µs | 148 / 1.00 · 6.5 ms |

- **C 는 모든 창·샷·카메라에서 LM 과 같은 답을 낸다**(차이 1 % 안팎). 계산은 150–300배 적다. PRD 의 "샷 하나 역보정 ≤ 20 ms (폰)" 보다 수백 배 여유가 생긴다.
  그 여유로 사후 표본(불확실도), 여러 가설 추적, 안경·저사양 기기에서 실시간 역보정을 할 수 있다.
- **B 는 드라이버 0.2 s 이상에서 LM 과 비슷하다**(1500–3000배 적은 계산). 짧은 창과 아이언에서는 C 가 필요하다. 축마다 따로 맞추는 2차식(9개)이 장의 꼴(8개, 항력·양력이 같은 r)보다 정보를 흘린다.
  항력 투영을 더하면 드라이버 0.2 s 의 스핀 오차가 180 → 133 rpm 으로 준다. 공유 포화의 실용적 이득이다.
- **0.05 s(실내 3 m)는 어느 방법이든 스핀 오차가 약 1200 rpm 이다**(사전분포로 돌아감). 계산이 아니라 정보의 한계다. 실내에서는 여전히 벽 반동(`screen`)이 필요하다.
- 가짜 프레임 CSV 로 실제 경로를 확인했다(`fieldinv --synth-csv` → `fieldinv --csv --compare`, `spininv --csv`). 드라이버 0.2 s 에서 C 는 2642 rpm·271.2 yd 를 79 µs 에 냈다.
  같은 CSV 에서 spininv 는 2640 rpm·271.4 yd 를 9.6 ms 에 냈다(참값 2686 rpm·270.0 yd). CSV 의 `# cam` 원근 보정도 C 의 잔차에 넣었다.
- 아직 안 한 것: `screen`(벽 반동)의 LM 도 같은 방식으로 바꿀 수 있다. 벽 전 3 m 비행과 반동 뒤 비행을 테일러 닫힌 꼴로, 반동은 이미 대수식이다. 실제 폰 영상으로는 확인하지 않았다.

재현: `cd flightbench && ./target/quick/fieldinv 60` (옆 카메라), `./target/quick/fieldinv 60 --cam behind`.

### 스크린을 스핀 센서로 (`flightbench/src/bin/screen.rs`)

실내 3 m 비행만으로는 스핀이 안 보인다. 대신 스크린 충돌 식을 관측 식에 넣는다. 굴림 영역에서
$\Delta v_t=-k_t\,(v_t+(\boldsymbol\omega\times\mathbf r_c)_t)$, $\Delta\boldsymbol\omega=\tfrac{5}{2R^2}\,\mathbf r_c\times\Delta\mathbf v_t$ 라서
1000 rpm 차이가 반동 접선 속도 약 0.6 m/s 차이가 된다(강체 $k_t=2/7$; 천 스크린은 $k_t$ 를 미지수로 둔다).

| 대각 카메라, 240 fps, σ 5 mm, 반동 0.1 s | 드라이버 캐리 | 드라이버 스핀 | 7번 캐리 | 웨지 캐리 |
|---|---|---|---|---|
| 스크린 없이 3 m 비행만 | 9.7 yd | ±1247 rpm | 3.4 yd | 2.0 yd |
| **스크린 반동, $k_t$ 보정됨** | **1.7 yd** | **±202 rpm** | **0.9 yd** | **0.3 yd** |
| 스크린 반동, $k_t$ 모름 | 5.2 yd | ±838 rpm | 1.7 yd | 0.4 yd |

$k_t$ 는 스크린 상수라 샷끼리 공유된다. 여러 샷을 함께 맞추는 자가 보정으로 5샷에 ±0.006, 40샷에 ±0.0023 (보정됨 기준 ±0.01 보다 좋음).
단 자가 보정은 참 스핀의 평균이 투어 회귀와 같다는 가정에 기댄다. 모든 수치는 시뮬레이션이며, 천 스크린이 굴림 꼴 충돌 식을 따르는지는 실측으로 확인해야 한다.

위기 지수 N 은 `SharedRe<N>` 의 형 매개변수라 곱 몇 번으로 접힌다(실행 시간 지수로 두면 f64 경로가 480 → 930 ns 로 느려졌다).

**꼴 찾기 2차** (`models_search.txt`, 투어 23행 CV 로만 고름). 항력 위기 인자 $q=1/(1+(Re/r_0)^n)$ 를 다른 항에도 거는 꼴 7개와 저스핀 양력 멱 2개를 시험했다.

- 기각: 양력 위기 $C_L=c\,r(1-fq)$, 포화 척도 위기, 스핀 감쇠 자유, 초임계 배경 기울기, 저스핀 양력 멱 $r^p$(자료가 $p\to1.5$ 로 문헌 $S^{0.4}$ 과 반대 방향).
- 위기의 가파름 $n$ 단면 (CV 종합): 4 → 2.823, 6 → 2.760, 8 → 2.713, **12 → 2.675**, 16 → 2.681. $n$ 을 자유로 두면 상한 12 에서 2.540 이지만 상한을 40 으로 넓히면 2.768 이 되어,
  CV 차 약 0.2 는 최적화 시작점의 흔들림 안이다. 그래서 $n=12$ 로 고정했다. 맞춘 $r_0\approx7.4\times10^4$ 는 문헌의 골프공 임계 영역(4–8e4) 안이다.

**새 기본 장 '공유위기12'** (6매, `engine.rs` `default_field()`, PGA 12행 세 양만 훈련):

$$
C_D=v+\frac{e}{1+(Re/r_0)^{12}}+d\,r,\qquad C_L=c\,r,\qquad r=\frac{S}{1+lS}
$$

  정점은 3단 고리(안쪽 ≈4 m 격자, 3 km 까지 23 m, 15 km 까지 117 m)와 치마로 이음매를 가렸다. 색은 정점 색(초지·마른 풀·숲 바닥·바위·고산 회색, 젖은 둑)이고 흑백 잔디 질감과 법선 지도가 가까운 곳의 결을 준다.
  멀리는 지수 안개(FogExp2 0.00017: 3 km 에서 21 %, 6 km 에서 60 %, 12 km 에서 안개색)로 능선이 겹겹이 푸르스름하게 바랜다. 카메라 far 를 4 km → 30 km 로 올렸다.
- **호수** (`terrain.ts` carve, `Water.tsx`): 물 다각형 안을 가장자리에서 5.5 m 에 걸쳐 1.7 m 파서 자연스러운 둑과 물가선을 만들고(섬 `land` 는 그대로), 수면 판에 깊이 색 지도(얕은 청록 → 깊은 남색 + 거품)와 흐르는 잔물결 법선 지도, 숲이 비치는 어두운 지평선의 하늘 반사를 줬다.
- **숲** (`Forest.tsx`): 지형 높이장 위에 거리 구간별로 심는다(가까이 6.5 m 간격·층진 수관+줄기·그림자, 중간 16 m, 먼 46 m 간격). 심는 확률은 지형의 `forest()` 와 같은 함수라 땅 색(숲 바닥)과 맞는다.
- **풀잎** (`RoughGrass.tsx`): **gaesup-world `Grass`**(바람에 흔들리는 인스턴스 풀잎)를 공 둘레 러프 칸에 3겹(0.09 / 0.15 / 0.26 m, 최대 28 만 장)으로 깐다. 공이 새로 놓일 때마다 칸을 다시 고른다. 페어웨이·그린·티는 질감만(풀잎은 러프에서 시작).
- **기물** (`Props.tsx`): 핀 깃발(바람 방향으로 뻗고 세기만큼 나부끼는 천, 정점 셰이더), 티 안내판(홀 번호·파·거리·이름), 100·150·200 yd 말뚝, 벙커 갈퀴, 벤치, 바위(호숫가·숲 가장자리, CC0 암석 질감), 갈대(호숫가 군락).
- **하늘·빛**: 앞 왼쪽 낮은 오후 해(고도 약 27°)라서 나무 그림자가 페어웨이를 가로지르고 능선이 역광으로 뜬다. 흐르는 구름 돔, 하늘색 환경광(IBL), gaesup `WorldPostProcessing`(AO·TRAA·블룸·채도 0.9).
- **연습장·메뉴**: 연습장도 같은 지형·숲·잔디 질감으로 올렸다(`rangeHole.ts` 가 연습장 구역을 자리표시 홀로 줌). 메뉴 배경 항공 촬영은 낮은 궤도로 바꿔 능선이 보인다.
- **공**: 딤플 336개 법선 지도(`ballDimples`)와 48×32 분할 구, **페어웨이·티·프린지 가장자리**는 알파 띠(`SoftEdge.tsx`)로 깎은 풀색이 러프로 번지게 했다(효과는 은은하다).
- **화면 디자인** (`ui/theme.css`): 유리 카드, 스코어바 느낌의 홀 카드, 금색 숫자, 알약 클럽 칩, 광택 있는 스윙 미터. 레이아웃은 그대로.
- **gaesup-world 에서 쓴 것·안 쓴 것**: 렌더러(WebGPU→WebGL), `CascadedSun`, `SkyEnvironment`, `WorldPostProcessing`, `Grass`, 캐릭터 컨트롤러, 엔진 프레임 단계. 안 쓴 것: 나무 기물(`SakuraBatch`, oak·pine·birch 등)은 만화 같은 덩어리 + 검은 점 입자라서 실사 목표와 맞지 않아 뺐고
  (직접 만든 층진 소나무·활엽수를 썼다), `FlagMesh`·`Water` 는 공개 export 가 아니거나 사각 타일 기준이라 같은 물결 식·다각형 호수를 직접 구현했다. 타일 지형(`TileSystem`)은 계단식 블록 높이라 매끄러운 산에는 쓰지 않았다.
- **성능** (같은 기계, 헤드리스, 프레임 한도 해제 `--pass perf`): 티 샷 장면 **190 fps (5.2 ms)**, 페어웨이·호수 **260 fps**, 홀 전체 보기 **310 fps**; 삼각형 약 1000–1800 만, 드로우콜 60–95. `?quality=low` 는 나무·풀잎 밀도를 35 % 로 줄여 삼각형 700 만, 245 fps.
  첫 프레임까지 약 2.5 초(지형 생성 0.3 초 + 잔디 질감 생성 0.2–0.4 초 × 3). 지형·숲·질감은 홀을 바꿀 때 캐시에 남아 메모리가 늘어난다(9홀 한 바퀴에 지오메트리 66 → 111, 텍스처 74 → 102).
- **검증**: `npm test` 66개(지형 시험 24개 추가: 구역 안 y = 0, 밖은 멀수록 높음, 호수 −1.7 m·섬 0, 지오메트리 유한·단위 법선), `tsc`, `npm run build`, `npm run smoke`(WebGPU 16단계 통과, 문제 0) 통과. WebGL 폴백(`?renderer=webgl`)도 같은 장면이 뜨는 것을 확인했다(후처리 없음, 풀잎은 gaesup 의 클래식 경로). SwiftShader 소프트웨어 렌더링은 안 돌려 봤다.
- **한계**: 플레이 구역은 여전히 평지다(물리가 평지라서 지형 기복은 구역 밖에서만). 캐릭터(gaesup 의 만화풍 GLB)는 실사 장면과 어울리지 않는다 — 숨기거나 바꾸는 선택이 남았다. 풀잎은 러프에서만이고 페어웨이 가장자리는 아직 선이 또렷하다.
  물은 반사가 하늘 환경광뿐(주변 나무는 안 비친다). 나무는 절차적 모양이라 가까이서 보면 한 가지 틀이 반복된다.

## 허점과 반례

- π/4 와 Z 의 상수는 훈련 자료를 본 뒤 고른 [경험식]/[가설]이다. 단순 상수 42쌍 점검에서 Z 는 특별하지 않았고, $(v_{\text{ev}}, h)$ 에 1차원 골짜기가 있어 이 자료는 조합 하나만 정한다.
- $S\to0$ 극한의 항력 $C_D(0)=0.388$ 은 자료가 정하지 않은 값이며 문헌값보다 높다.
- 스핀 감쇠($C_M=0.012\,S$)는 고정 가정이고 검증하지 않았다.
- 반례: F1(π/2 포화), F2(오일러꼴), log 저장, 진공해 배경 비율 저장, 4차원 장의 기울기 축 펼치기(캐시 초과),
  **각도 잠금의 저스핀 외삽(USGA 드라이버)**, **Penner + 브리스톨 계수 지면 모형(USGA 런)**.
- 레이놀즈수 의존 항 두 꼴($e/|u|$, 계단)은 보류에서 기각됐다. 아이언 착지각 4–6° 계통 오차의 원인은 미상이다.
- 투어 평균표에는 입력 산포가 없어 원리 1(분포 평균)을 적용하지 못했다. 사이드 스핀은 모형만 있고 실측 대조가 없다. 지면 모형은 검증되지 않았다.
- **[반례] 캐리만으로 보정하면 궤적 꼴이 틀린다.** 이전 표의 캐리 RMSE 비교는 꼴을 보지 않은 판정이었다.
- **[반례] 계수 6개 중 4개는 자료가 정하지 않는다.** 투어 최적점의 느슨한 방향 2개(±14 %·±25 %)와 묶음 넷으로 맞춤 2개 장(K2)이 같은 보류 성적을 낸다. 6개 장의 2–4샷 보정은 최악 13–25 yd 로 무너진다.
- **[열림] 저스핀 항력.** 발사 스핀 비 0.075 아래 실측 33샷을 +3–7 yd 멀리 보낸다. 장의 무스핀 항력 $v\approx0.145$ 는 문헌의 무회전 골프공 값보다 낮고, 투어·FS 에는 이 영역이 없다.
- **[반례] 양면 레이놀즈 평균(CE 원리 1 을 위기 인자에)**: $r_0$ 는 문헌 임계 쪽(4.8e4)으로 가지만 CV 2.35 → 3.00, 실측 캐리 +3.4 yd 치우침. 양력 위기를 항력 위기의 도함수(깊이 3/4)·면 차이(선형)로 끌어내는 꼴도 기각.
- **[반례] 캐리·높이가 맞아도 착지 상태가 틀리다.** 착지 속력 −5.3 mph, 착지각 +2.8° (실측 드라이버 767샷). 기존 엔진 OpenFairway 는 착지 속력에서 이긴다(편향 −0.9 mph). 총거리는 이 때문에 롤 모형을 따로 얹어야 한다.
- **[반례] 투어 평균표 2.8 yd 는 샷 단위 정확도가 아니다.** 같은 모형이 실측 드라이버 샷에서는 6.3 yd(깨끗한 공), 발사 조건이 같아도 4.7 yd 흩어진다. 공 종류가 다르면 한 번에 약 10 yd 어긋난다.

```sh
pip install numpy scipy
python -B onefield_carry.py
python -B run_higgs.py          # unfolded_field.npz 생성
python -B zero_param.py
python -B compress_field.py
python -B fewshot.py            # 약 20분
python -B field3d.py

python -B fewshot_reg.py        # 약 20분

cd flightbench && cargo run --release
cargo run --release --bin field4
cargo run --release --bin h2      # 약 35 초

cargo run --profile quick --bin quick   # 약 1.5 초, 항은 models.txt

cd ../golf-core && cargo test --lib                     # 코어 단위 시험 5개
cargo run --release --bin bench             # 정밀도·속도 표 (약 1 분)
sh build-wasm.sh && node bench/bench.mjs   # wasm·JS 표
```
