# 실측 자료

영상 원본(`*.mp4`, `*.mov`)은 용량 때문에 커밋하지 않는다. 촬영 조건과 결과만 남긴다.

- `results.csv`: `/shot` 명령이 한 줄씩 추가 (날짜, 영상, fps, 벽 m, k_t, 스핀, 축, 캐리, 카이제곱/자유도)
- 촬영 메모: 기종, 화각, 판 재질, 벽 거리, 조명, 런치 모니터 대조값(있으면)

## 지금 있는 실측 (2026-10-12)

| 종류 | 내용 | 검증하는 것 | 검증하지 못하는 것 |
|---|---|---|---|
| 공개 TrackMan 드라이버 약 1만 샷 | `tools/fetch_trackman_public.sh` 로 `external/trackman_public/` 에 받음 (커밋 안 함, 출처 라이선스 미표기) | **비행 모형**: 잰 볼스피드·발사각·방향·스핀·축 → 캐리·옆 편차·최고 높이·착지각 | 폰 영상 → 발사 조건 역보정 |
| 폰 영상 | **아직 없음** | – | – |

결과와 해석은 README 의 "실측 대조" 절. 도구는 `flightbench/src/bin/real.rs`.
TrackMan 값도 기기가 낸 측정이다(레이더). 캐리·착지각은 추적한 궤적에서 구한 값이고, 마지막 데이터 점이 캐리의 90% 이상인 샷만 쓴다.
기온·고도·바람 기록은 없다.

## 폰 영상 촬영 규약 (M1)

PRD F1–F3 을 판정하려면 다음을 같이 남긴다. 런치 모니터 값이 없으면 F3·F5 는 판정하지 못한다.

1. 폰: 240 fps(아이폰 슬로모) 우선, 안 되면 120/60 fps 와 그 사실을 적는다. 옆에서 수평 고정, 노출 고정, 출발점과 벽이 한 화면에.
2. 보정 던지기 5회 (벽에 닿을 때 공이 올라가는 중) → `tools/run_shot.sh 영상 240 hfov 벽m --throw`.
3. 샷: 아이언 20 + 드라이버 10 이상. 샷마다 **런치 모니터 값**(볼스피드, 발사각, 발사 방향, 스핀, 스핀축, 캐리, 있으면 착지각)을 같은 표에 적는다.
4. 공 종류를 적는다. 같은 발사 조건에서도 공이 다르면 캐리가 약 10 yd(약 6%) 달라진다 (README "실측 대조").
5. 기온, 고도, 바람(대략)을 적는다.
6. 파일 이름: `날짜_기종_클럽_번호.mp4`. 영상 원본은 이 폴더 아래에 두되 커밋하지 않는다(gitignore 가 막는다).

Meta 안경 카메라(Wearables Device Access Toolkit)는 스트림이 720p·30 fps 로 제한돼서(문서·보도 기준, 공식 문서로 재확인 필요) 이 측정에 쓰지 못한다.
