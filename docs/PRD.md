# PRD — 폰 하나로 집에서 스크린골프 (golf-onefield)

작성 2026-10-08 · 상태: 시뮬레이션 검증 완료, 실측 검증 전

## 1. 한 줄

폰 카메라 한 대와 벽(판) 한 장으로 볼스피드·발사각·**스핀**을 재고, 장 하나 비행 엔진으로 궤적을 계산해,
TV나 헤드셋에 띄운다. 센서·빔프로젝터·부스 없이 집에서 스크린골프.

## 2. 문제

- 집에 스크린골프를 차리려면 런치 모니터(수십만~수천만 원) + 프로젝터 + 스크린 + 공간이 필요하다.
- 폰 카메라로는 스핀을 직접 못 잰다. 240 fps 에서 3000–9000 rpm 공은 프레임 사이 75–225° 돌아 바퀴 수를 셀 수 없다.
- 실내 3 m 비행만으로는 스핀이 궤적에 드러나지 않는다(시뮬레이션: 드라이버 캐리 오차 ±7–10 yd).

## 3. 핵심 아이디어 (이 저장소의 근거)

| 구성 | 내용 | 근거 파일 |
|---|---|---|
| 장 하나 비행 엔진 | 공유 포화 장 + 가파른 항력 위기(공유위기12): $C_D=v+\frac{e}{1+(Re/Re_0)^{12}}+d\,r$, $C_L=c\,r$, $r=S/(1+lS)$ | `flightbench/models.txt`, `src/engine.rs` (`default_field`) |
| 빠른 적분 | f32×16 (AVX-512 / 애플 실리콘 NEON), τ 걸음, 샷당 약 0.2 µs, 적분 오차 3e-4 yd, M4 Pro 14스레드 3.2e7 샷/초 | `src/engine.rs` (`stream`), `bin/h2.rs` |
| 벽을 스핀 센서로 | 굴림 충돌 $\Delta v_t=-k_t(v_t+(\omega\times r_c)_t)$ → 반동 방향에서 스핀 역산 | `bin/screen.rs` |
| 닫힌 꼴 + LM | $\omega=-(\Delta v_t/k_t+v_t)/R$ 로 출발, 궤적도 장의 닫힌 꼴(테일러 조각, 적분 없음)로 LM 한 번 (데스크톱 0.2–0.8 ms/샷, 2026-10-13. 예전 RK4 궤적 9–29 ms) | `bin/screen.rs` (`closed_form`, `sample_cf`) |
| 벽 보정 | 손으로 벽에 던지기(스핀≈0)로 $k_t$, $e$ 측정 / 샷 공유 자가 보정 | `screen --throw`, `screen --selfcal` |
| 영상 → 위치 | 배경 차분 추적, 벽 충돌 교점으로 축척, 원근 보정 | `tools/track_ball.py` |

## 4. 현재 성능 (모두 시뮬레이션·가짜 영상)

자료 대비 비행 모형 (PGA 투어로 보정, 다른 자료로 판정):

| RMSE | LPGA 캐리/높이/착지 | USGA 캐리 (전체/아마) | 비교: OpenFairway 재맞춤 |
|---|---|---|---|
| 공유위기12 | 2.78 yd / 1.68 yd / 3.05° | 7.42 / 4.64 yd | 3.42 / 2.98 / 5.30 · 8.06 / 5.49 |

측정 (폰 대각선, σ 5 mm, 단단한 벽 3 m, 반동 0.2 s):

| | 240 fps | 60 fps |
|---|---|---|
| 드라이버 캐리 | 2.3 yd | 4.6 yd |
| 7번 캐리 | 0.6 yd | 1.1 yd |
| 웨지 캐리 | 0.3 yd | 0.56 yd |

가짜 영상 왕복 (720p, 공 반지름 6.5 px, `tools/e2e_synth.sh`): 7번 168.4 (참 168.5), 드라이버 265.8 (270.0), 웨지 103.7 (104.7) yd, 던지기 보정 $k_t$ 0.2848 (0.2857).

위 측정 수치에는 위치 잡음만 들어 있다. 기하·보정의 계통 오차는 8절 위험 표와 README '벽 반동 스핀 센서의 계통 오차' 참고.

## 5. 사용자와 흐름

대상: 집에 매트·그물이 있거나 둘 수 있는 아마추어. 첫 시장은 연습용 판독기.

1. **설치 (1분)**: 판(합판·고무판)을 그물 안 3 m 앞에, 폰을 옆(또는 대각선)에 세움. 화면에 출발점과 벽이 다 들어오는지 앱이 확인.
2. **보정 (1분)**: 공을 손으로 벽에 3–5번 던짐(벽에 닿을 때 공이 아직 올라가는 중). 앱이 $k_t$, $e$ 를 표시하고 강체에서 크게 벗어나면 경고.
3. **확인 샷 3–5개**: 샷 공유 자가 보정으로 $k_t$ 수렴 → "준비 완료".
4. **플레이**: 샷마다 캐리·총거리·스핀·스핀축·볼스피드·발사각 ± 불확실도, 궤적 애니메이션. 흐릿한 샷은 "다시 쳐 주세요".
5. **화면**: 폰 → TV 미러링 / WebXR(Quest 3, Galaxy XR) 3D 코스 / 안경 HUD(결과 표시만). 측정은 항상 폰(240 fps)이고 안경은 표시 전용이다: 안경 카메라는 SDK 스트림이 720p·30 fps 로 제한돼 공 추적에 못 쓴다.

## 6. 요구 사항

### 기능 (P0 = 첫 출시)

| ID | 요구 | 수용 기준 |
|---|---|---|
| F1 P0 | 240 fps 촬영, 공 자동 검출·추적 | 실제 영상 20샷 중 18샷 이상 끝까지 추적, 위치 오차 ≤ 5 mm (기준 길이 대비) |
| F2 P0 | 벽 보정(던지기) | 같은 벽 5회 반복 시 $k_t$ 흔들림 ≤ ±0.01 |
| F3 P0 | 벽 반동 스핀 역보정 | 런치 모니터 대조 30샷: 아이언 캐리 RMSE ≤ 3 yd, 스핀 RMSE ≤ 600 rpm |
| F4 P0 | 결과 표시 + 불확실도 | 임팩트 후 300 ms 안에 표시 |
| F5 P1 | 드라이버 | 캐리 RMSE ≤ 8 yd (대조 30샷). 발사 조건을 런치 모니터 값으로 줘도 6.3 yd 라(공개 TrackMan 실측, README "실측 대조") 6 yd 는 영상 오차가 더해지면 닫히지 않는다 |
| F6 P1 | 3D 코스 (WebXR) | Quest 3 브라우저 72 fps |
| F7 P1 | 대각선 카메라 (사이드 스핀) | 스핀축 RMSE ≤ 5° |
| F8 P2 | 60 fps 기기 (모션 블러 관측 식) | 아이언 캐리 RMSE ≤ 3 yd |
| F9 P2 | 헤드셋 단독 (패스스루 카메라) | 벽이 화면에 들어오는지 실측 후 결정 |
| F10 P2 | Meta Ray-Ban Display 결과 HUD (웹 앱) | 600×600 화면에 캐리·스핀·간단한 2D 궤적. 같은 `golf-core` wasm 으로 계산. 기기에서 WebAssembly 지원을 먼저 확인 |

### 비기능

- 연산: 샷 하나 역보정 ≤ 20 ms (폰 CPU), 비행 계산 ≤ 1 µs. 현황(데스크톱, 2026-10-12): wasm SIMD 0.63–0.71 µs, 스칼라 wasm f64 1.85 µs, 네이티브 AVX-512 0.155 µs. 역보정(벽 반동, 닫힌 꼴 궤적, 2026-10-13) 0.2–0.8 ms, 비행만 역보정(`fieldinv`) 15–60 µs. 폰·안경 CPU 는 미측정.
- 오프라인 동작. 영상은 기기 밖으로 내보내지 않는다(기본).
- 안전: 단단한 판 앞에 반동 그물 필수, 설치 화면에서 경고.

## 7. 범위 밖 (이번 판)

지면(바운스·구름) 모형은 검증 실패 상태(`ground.py`, USGA 런 기준보다 나쁨) — 총거리는 표시하지 않거나 '참고'로만.
바람·고도, 퍼팅, 멀티플레이, 코스 저작.

## 8. 위험과 열린 질문

| 위험 | 영향 | 대응 |
|---|---|---|
| 실제 판의 반동이 굴림 충돌 식과 다름 (공 변형, 고속). 접선 컴플라이언스로 $k_t$ 가 입사각·속도마다 다를 수 있음(PING 2020) | $k_t$ 5% 차이 → 스핀 ±340–650 rpm | 런치 모니터 대조로 $k_t$ 를 속도·입사각별로 잼, 필요하면 $k_t(v_n,\theta)$ |
| 벽·카메라 기울기 (벽 법선 대 화면 축) | 0.25° → 드라이버 스핀 ±650 rpm, 0.5° → ±1,300 rpm·캐리 −15 yd | 판 앞면 모서리를 영상에서 선 맞춤(렌즈 왜곡 보정 후), 모형에 벽 법선 각 매개변수 추가, 평평하고 단단한 판 |
| 던지기 공의 스핀 (가정 0 ± 300 rpm) | 600 rpm → $k_t$ +9% → 7번 스핀 −1,100 rpm | 스핀이 알려진 보정 발사(경사로에서 굴려 보내기 $\omega=v/R$ 등) |
| 단단한 벽의 반동 속도 | 드라이버 97 mph 가 치는 쪽으로 | 판을 뒤로 눕혀 반동을 위쪽 그물로, 반동 경로 설계 |
| 롤링 셔터·렌즈 왜곡·조명 | 위치 오차 증가 | 기종별 보정, 렌즈 왜곡 계수, 노출 고정 |
| 사람·클럽이 배경에 섞임 | 추적 실패 | 관심 영역(출발점 앞쪽), `--ball` 수동 지정, 이후 학습 검출기 |
| 화각(hfov) 모름 | 축척은 벽으로 잡아 영향 작음, 원근 보정에 영향 | 기종 표, 기준 길이(`--scale`) |
| 사용자 스핀 분포가 투어와 다름 | 자가 보정 치우침 | 던지기 보정을 기본으로 |
| 공 종류가 다름 (Medium 공: 같은 발사 조건에서 캐리 +10 yd) | 캐리 오차 | 공 종류 보정 샷, 사용자에게 공 종류 입력. 한 배율로는 높이 꼴이 안 맞아 실측 더 필요 |
| 같은 발사 조건에서도 캐리가 4.7 yd 흩어짐 (바람·접촉) | 캐리 목표의 하한 | 판정을 발사 조건 수준에서도 한다. 총거리·캐리는 불확실도 구간과 함께 표시 |
| 안경 카메라 720p·30 fps (Device Access Toolkit) | 안경으로 측정 불가 | 측정은 폰, 안경은 표시. 문서 변경 가능성이 있어 출시 전 재확인 |
| Ray-Ban Display 웹 앱: 개발자 미리보기, 공개 스토어 없음, WebAssembly·WebGL 지원 미확인 (보도 기준) | F10 일정 | 기기에서 `golf-core` wasm 을 직접 올려 확인. 안 되면 순수 JS 코어(wasm 의 8–10배 느림, 같은 답)로 대체 |
| 비행 모형의 착지 상태가 실측과 다름 (착지 속력 −5.3 mph, 착지각 +2.8°) | 총거리·착지 후 모든 계산 | 롤 모형을 실측에 따로 맞춤(드라이버 한정, 총거리 ±8 yd). 근본 원인은 미해결, 폰 영상 실측 전에는 총거리를 '참고'로만 |
| 선행 특허·제품 | 사업성 | 실측 통과 즉시 선행 조사 + 가출원 |
| 큰 회사의 모방 | 사업성 | 출원, 속도 |

## 10. 저장소 지도

- `flightbench/` 러스트: `src/engine.rs`(엔진), `src/harness.rs`·`bin/quick.rs`(항 시험대), `bin/screen.rs`(벽 센서·CSV), `bin/spininv.rs`(비행만 역보정), `src/openfairway.rs`(비교 엔진)
- `tools/` 영상 파이프라인: `track_ball.py`, `run_shot.sh`, `make_synth_video.py`, `e2e_synth.sh`
- `golf-core/` 이식용 러스트 코어 (f32/f64, 3차원 비행) → wasm, 정밀도·속도 벤치
- `web3d/` r3f + gaesup-world 3D 골프 게임 (9홀·모드·지면 모형·TS 엔진). 실사 장면(지형·숲·호수·기물)은 `web3d/src/photo/`, 점검 도구는 `web3d/scripts/{shots,perf}.mjs`
- `web/golf-game/` r3f + gaesup-world 3D 골프 홀 프로토타입 (샷 궤적은 wasm 코어, `web3d` 보다 앞선 판)
- `web/glasses-hud/` Ray-Ban Display HUD 겸 기능 점검 페이지 (`sh build.sh` 후 정적 호스팅)
- `flightbench/src/bin/real.rs`, `tools/analyze_real.py` 공개 TrackMan 실측 샷 대조
- `web/spin_inverse.html` WebGPU 역보정 데모
- 연구 기록과 반례: `README.md`
