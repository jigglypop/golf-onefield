# PRD — 폰 하나로 집에서 스크린골프 (golf-onefield)

작성 2026-10-08 · 상태: 시뮬레이션 검증 완료, 실측 검증 전

## 1. 한 줄

폰 카메라 한 대와 벽(판) 한 장으로 볼스피드·발사각·**스핀**을 재고, 장 하나 비행 엔진으로 궤적을 계산해,
TV나 헤드셋에 띄운다. 센서·빔프로젝터·부스 없이 집에서 스크린골프.

## 2. 문제

- 집에 스크린골프를 차리려면 런치 모니터(수십만~수천만 원) + 프로젝터 + 스크린 + 공간이 필요하다.
- 폰 카메라로는 스핀을 직접 못 잰다. 240 fps 에서 3000–9000 rpm 공은 프레임 사이 75–225° 돌아 바퀴 수를 셀 수 없다.
- 실내 3 m 비행만으로는 스핀이 궤적에 드러나지 않는다(시뮬레이션: 드라이버 캐리 오차 ±7–10 yd).

## 3. 핵심 아이디어 (이 저장소의 근거)

| 구성 | 내용 | 근거 파일 |
|---|---|---|
| 장 하나 비행 엔진 | 공유 포화 장 + 항력 위기: $C_D=v+\frac{e}{1+(Re/Re_0)^4}+d\,r$, $C_L=c\,r$, $r=S/(1+lS)$ | `flightbench/models.txt`, `src/engine.rs` |
| 빠른 적분 | f32×16 AVX-512, τ 걸음, 샷당 약 0.2 µs, 적분 오차 3e-4 yd | `src/engine.rs` (`stream`), `bin/h2.rs` |
| 벽을 스핀 센서로 | 굴림 충돌 $\Delta v_t=-k_t(v_t+(\omega\times r_c)_t)$ → 반동 방향에서 스핀 역산 | `bin/screen.rs` |
| 닫힌 꼴 + LM | $\omega=-(\Delta v_t/k_t+v_t)/R$ 로 출발, LM 한 번 (2–10 ms/샷) | `bin/screen.rs` (`closed_form`) |
| 벽 보정 | 손으로 벽에 던지기(스핀≈0)로 $k_t$, $e$ 측정 / 샷 공유 자가 보정 | `screen --throw`, `screen --selfcal` |
| 영상 → 위치 | 배경 차분 추적, 벽 충돌 교점으로 축척, 원근 보정 | `tools/track_ball.py` |

측정 (폰 대각선, σ 5 mm, 단단한 벽 3 m, 반동 0.2 s):

| 7번 캐리 | 0.6 yd | 1.1 yd |

## 5. 사용자와 흐름

대상: 집에 매트·그물이 있거나 둘 수 있는 아마추어. 첫 시장은 연습용 판독기.

1. **설치 (1분)**: 판(합판·고무판)을 그물 안 3 m 앞에, 폰을 옆(또는 대각선)에 세움. 화면에 출발점과 벽이 다 들어오는지 앱이 확인.
2. **보정 (1분)**: 공을 손으로 벽에 3–5번 던짐(벽에 닿을 때 공이 아직 올라가는 중). 앱이 $k_t$, $e$ 를 표시하고 강체에서 크게 벗어나면 경고.
3. **확인 샷 3–5개**: 샷 공유 자가 보정으로 $k_t$ 수렴 → "준비 완료".
4. **플레이**: 샷마다 캐리·총거리·스핀·스핀축·볼스피드·발사각 ± 불확실도, 궤적 애니메이션. 흐릿한 샷은 "다시 쳐 주세요".
5. **화면**: 폰 → TV 미러링 / WebXR(Quest 3, Galaxy XR) 3D 코스 / 안경 HUD(결과 표시만).

## 6. 요구 사항

### 기능 (P0 = 첫 출시)

| ID | 요구 | 수용 기준 |
|---|---|---|
| F1 P0 | 240 fps 촬영, 공 자동 검출·추적 | 실제 영상 20샷 중 18샷 이상 끝까지 추적, 위치 오차 ≤ 5 mm (기준 길이 대비) |
| F2 P0 | 벽 보정(던지기) | 같은 벽 5회 반복 시 $k_t$ 흔들림 ≤ ±0.01 |
| F3 P0 | 벽 반동 스핀 역보정 | 런치 모니터 대조 30샷: 아이언 캐리 RMSE ≤ 3 yd, 스핀 RMSE ≤ 600 rpm |
| F4 P0 | 결과 표시 + 불확실도 | 임팩트 후 300 ms 안에 표시 |
| F5 P1 | 드라이버 | 캐리 RMSE ≤ 6 yd (대조 30샷) |
| F6 P1 | 3D 코스 (WebXR) | Quest 3 브라우저 72 fps |
| F7 P1 | 대각선 카메라 (사이드 스핀) | 스핀축 RMSE ≤ 5° |
| F8 P2 | 60 fps 기기 (모션 블러 관측 식) | 아이언 캐리 RMSE ≤ 3 yd |
| F9 P2 | 헤드셋 단독 (패스스루 카메라) | 벽이 화면에 들어오는지 실측 후 결정 |

### 비기능

- 연산: 샷 하나 역보정 ≤ 20 ms (폰 CPU), 비행 계산 ≤ 1 µs.
- 오프라인 동작. 영상은 기기 밖으로 내보내지 않는다(기본).
- 안전: 단단한 판 앞에 반동 그물 필수, 설치 화면에서 경고.

## 7. 범위 밖 (이번 판)

지면(바운스·구름) 모형은 검증 실패 상태(`ground.py`, USGA 런 기준보다 나쁨) — 총거리는 표시하지 않거나 '참고'로만.
바람·고도, 퍼팅, 멀티플레이, 코스 저작.

## 8. 위험과 열린 질문

| 위험 | 영향 | 대응 |
|---|---|---|
| 실제 판의 반동이 굴림 충돌 식과 다름 (공 변형, 고속) | 스핀 오차 증가 | 던지기·샷 보정으로 $k_t$ 를 직접 잼, 필요하면 충돌 식에 접선 반발 계수 추가 |
| 롤링 셔터·렌즈 왜곡·조명 | 위치 오차 증가 | 기종별 보정, 렌즈 왜곡 계수, 노출 고정 |
| 사람·클럽이 배경에 섞임 | 추적 실패 | 관심 영역(출발점 앞쪽), `--ball` 수동 지정, 이후 학습 검출기 |
| 화각(hfov) 모름 | 축척은 벽으로 잡아 영향 작음, 원근 보정에 영향 | 기종 표, 기준 길이(`--scale`) |
| 사용자 스핀 분포가 투어와 다름 | 자가 보정 치우침 | 던지기 보정을 기본으로 |
| 선행 특허·제품 | 사업성 | 실측 통과 즉시 선행 조사 + 가출원 |
| 큰 회사의 모방 | 사업성 | 출원, 속도 |
